# API Specification

> REST/JSON, versioned under `/api/v1`. The OpenAPI document generated by FastAPI is the machine-readable contract; the frontend client is generated from it (`openapi-typescript`). This file defines conventions and the Release 1 endpoint set. Permissions reference the matrix in `SECURITY.md` §3. Semantics of calculation fields: `BUSINESS_LOGIC.md`.

## 1. Conventions

| Topic | Rule |
|---|---|
| Base path | `/api/v1`. Breaking changes → `/api/v2`; additive changes stay in v1. Deprecations announced via `Deprecation`/`Sunset` headers |
| Format | `application/json; charset=utf-8`. File uploads `multipart/form-data` (files endpoints only) |
| Auth | Session cookie (`__Host-session`, `HttpOnly; Secure; SameSite=Lax`). Mutating requests (`POST/PUT/PATCH/DELETE`) require header `X-CSRF-Token` equal to the CSRF cookie value |
| Tenant | Active tenant is part of the session. The client never sends `tenant_id`; any `tenant_id` in a body is rejected (422). Switching: `POST /auth/switch-tenant` |
| IDs | UUID strings |
| Money | **Decimal strings**, e.g. `"2200.00"`; never JSON numbers. Rates as strings (`"0.025"`). Quantities as strings |
| Dates/times | Dates `YYYY-MM-DD`; instants ISO-8601 UTC with `Z` |
| Naming | `snake_case` fields, plural resource paths, kebab-case multiword paths |
| Idempotency | `Idempotency-Key` header (UUID) **required** on: `POST /claim-batches`, `POST /claim-batches/{id}/submit`, `POST /calculation-runs`, `POST /imports`, `POST /remittances`, `POST /agreement-drafts/{id}/approve`, `POST /cases/{id}/write-off`. Same key + same body → original response replayed; same key + different body → 409 `idempotency_conflict`. Retained 24 h |
| Request id | Every response has `X-Request-Id`; errors echo it |
| Long operations | Return `202 Accepted` with a **job resource** (`{"job": {"id", "status", "progress", "result_url"}}`); poll `GET /jobs/{id}` |
| Caching | `Cache-Control: no-store` on authenticated responses |
| Rate limits | 429 with `Retry-After`; defaults: login 5/min/IP+account, general 600/min/user, uploads 30/min/user, AI endpoints 10/min/tenant |
| Limits | JSON body ≤ 1 MB (except draft payloads ≤ 5 MB); uploads per `SECURITY.md` |

### 1.1 Error envelope

All errors:

```json
{
  "error": {
    "code": "validation_error",
    "message": "One or more fields are invalid.",
    "details": [{"field": "rules.rounding.scale", "code": "out_of_range", "message": "Must be between 0 and 6."}],
    "request_id": "01JG…"
  }
}
```

| HTTP | `code` examples |
|---|---|
| 400 | `bad_request`, `unsupported_media_type` |
| 401 | `unauthenticated`, `session_expired`, `mfa_required`, `reauthentication_required` |
| 403 | `forbidden`, `csrf_failed`, `four_eyes_violation`, `mfa_enrollment_required` |
| 404 | `not_found` (also returned for other tenants' resources) |
| 405 | `method_not_allowed` |
| 409 | `conflict`, `already_claimed`, `idempotency_conflict`, `version_overlap`, `run_in_progress`, `invalid_state` |
| 410 | `invitation_expired`, `link_expired` (verify/reset/email-change links: expired, used or unknown; one generic answer) |
| 412 | `precondition_failed` (`If-Match` mismatch, §4) |
| 413 | `payload_too_large` |
| 422 | `validation_error`, `password_too_common` |
| 423 | `account_locked` |
| 429 | `rate_limited` |
| 500 | `internal_error` (generic message; details only in logs) |
| 503 | `unavailable` |

Cross-tenant access **always** returns `404 not_found`, never `403`, to avoid confirming existence.

### 1.2 Pagination, sorting, filtering

- Cursor pagination: `?limit=50&cursor=<opaque>` (max `limit` 200). Response:
  ```json
  {"data": [ ... ], "page": {"next_cursor": "…", "has_more": true}}
  ```
- Sorting: `?sort=-deadline_date,created_at` (allow-listed fields per endpoint; always with a deterministic tiebreaker `id`).
- Filtering: explicit query params per endpoint (e.g. `manufacturer_id`, `status`, `date_from`, `date_to`, `q`). Unknown params → 400. Multi-values via repetition (`status=open&status=to_reclaim`).
- Totals for lists that need them use a separate `GET …/summary` endpoint (avoid unbounded counts).

### 1.3 Validation

Pydantic v2 strict models on every request body and query model. Server validates everything the client validates, plus business validators. Money: regex `^-?\d{1,14}(\.\d{1,6})?$`, scale checked per field. Unknown fields rejected (`extra = forbid`). String lengths bounded. File names sanitised. Enumerations validated against allow-lists.

### 1.4 Authorization

Each router function declares its required permission (`policies.py`); a missing declaration fails CI (a test enumerates routes). Permission names: `<resource>.<action>`, e.g. `agreement.approve`. Ownership is by tenant (RLS) plus role; there is no per-record ACL in Release 1 except case `owner_user_id` for assignment (not restriction).

**Implementation notes (S4).**
- Permissions: reads `data.read`; create/edit/validate/`items:import`/submit `agreement.draft`; approve/reject/return/cancel `agreement.approve`.
- `ExtractionDetail.result` is published as OpenAPI component `ExtractionResult` (fields with confidence, evidence `{page, sheet, cell, quote, start, end, boxes}`, both passes, indicators, blocking, needs_acknowledgement, notes).
- The draft payload shape is published as OpenAPI component `Payload` (with `SpaRules`/`RebateRules`, `Header`, `Item`, `TierIn`, `CustomerRef`) although `DraftOut.payload`/`DraftUpdate.payload` are plain objects (invalid drafts are stored).
- Drafts are saved even when invalid; every save (create, `PUT`, `items:import`) runs the validator and returns `validation` `{valid, revision, validated_at, error_count, errors[], warnings[], references{unresolved_customers, unresolved_skus}}` (at most 1000 errors listed). Error fields are payload paths (`payload.items[3].sku`). Codes: pydantic type codes (`string_type`, `less_than_equal`, …) plus `required`, `unknown_field`, `invalid_choice`, `invalid_decimal`, `invalid_date`, `out_of_range`, `too_many_decimals`, `invalid_range`, `unresolved`, `duplicate`, `mismatch`, `not_applicable`, `incompatible`, `not_supported_until_release_2`, `unknown_adapter`, `not_increasing`, `invalid`, `agreement_exists`, `agreement_cancelled`, `version_overlap`, `stale_version`, `outside_amended_version`, `engine_rejected`. Warnings (`already_expired`, `measurement_period_mismatch`, `product_manufacturer_mismatch`) carry an `id` (`<code>:<field>`); `submit` takes `{acknowledged_warnings: [id…]}` and refuses with 422 `unacknowledged_warning` details otherwise. Errors → 422 `validation_error` on submit and approve. An amendment must keep the agreement's `agreement_type`, `external_number`, manufacturer and `name` (`mismatch`): the name is stored on the agreement, not per version.
- `GET/PUT /agreement-drafts/{id}` return `ETag: "<revision>"`; `PUT` and `items:import` require `If-Match` (412 otherwise). Editing is allowed in status `draft` only (409 `invalid_state`).
- `POST /agreement-drafts` `{source, agreement_id?, amends_version_id?, payload?, source_file_id?}`: with `amends_version_id` and no payload the payload starts as the amended version's terms; `spreadsheet_template` requires `source_file_id`; `ai_extraction` → 409 `ai_not_enabled` until S6.
- `POST /agreement-drafts/{id}/items:import` `{file_id, rate_format: fraction|percent, mapping?: {sku|reference_cost|deviated_cost|sell_price|rate|flat_amount|max_quantity|claim_uom: "<column>"}, header_row?, sheet?, dry_run?}` → `{dry_run, rows, items (dry run: first 100), draft}`. Synchronous, all-or-nothing, ≤ 20,000 rows; without `mapping` columns are recognised by name (e.g. `Catalog #` → sku, `Margin %` → rate, `Approved UoM` → claim_uom). Replaces the draft's items (new revision). Saved mapping templates (`import_type = agreement_items`) are not wired yet.
- `approve` needs `If-Match: "<revision>"` (the revision the approver reviewed; mismatch → 412, same convention as `PUT`), re-validates, enforces four-eyes (approver ∉ creator ∪ every revision editor; 403 `four_eyes_violation`, audited) and performs split-supersede in the request transaction: the amended version (active or expired) becomes `superseded`; the parts of its period before/after the amendment become copies with identical terms (`derived_from_version_id`); the new version has `supersedes_version_id`. Versions whose `valid_to` is before the business date are created `expired`. Exclusion violation → 409 `version_overlap`. Two concurrent approvals: one 200, the other 409 `invalid_state`.
- `POST /agreements/{id}/cancel {effective_date, reason}`: versions starting on/after the date → `cancelled`; a version spanning it is superseded by a copy ending the day before; the agreement gets `cancelled_at` and accepts no further drafts.
- `GET /agreement-versions/{a}/diff/{b}` → `{from_version_id, to_version_id, changes: [{path, before, after}]}` over header, rules, `customers[CODE].scope`, `items[SKU].<field>`, `tiers[n].<field>`. `GET /agreements` items carry `current_version` (active, covering the business date). Version lists and items are cursor-paginated.
- Expiry sweep (job `agreements_expiry_sweep`, daily per tenant, first enqueued on approval): expires versions past `valid_to`; audit `agreement_version.expiry_alert` for versions entering the 30-day window (notification hook until S9).
- `POST /agreement-drafts/{id}/preview-calculation` is built with the engine runs (S5).

Cases (S9): the queue lists `deadline_unknown` cases first, then by `deadline_date`, then id (`sort` accepts only that order).
`deadline_unknown` is `deadline_date = null`, not a case type. Every change to a case (`PATCH`, `transition`, `write-off`,
`reclaim`) needs `If-Match: "<revision>"` (412 `precondition_failed` otherwise) and returns the new `ETag`; `write-off`
also needs `Idempotency-Key`. With workspace four-eyes on, the first approver's `write-off` records a proposal (case stays
as is, event `write_off_proposed`) and a different approver completes it; the same person gets 403 `four_eyes_violation`.
`reclaim` returns `{case, adjustment_id}`. A completed `write-off` rejects the case's proposed/approved `recovery_reclaim` adjustment in the same transaction and is refused with 409 `reclaim_included` while that adjustment is in a claim batch; a pending write-off proposal is voided by any recovery or status change. `/cases/summary` groups carry `variance_amount`, `recovered_amount` and `written_off_amount` (the last is the sum of what was written off). Notes and reasons are trimmed; blank is 422. Reminders (14/7/3 days before the deadline) are created by the daily sweep and
mailed once as a digest; there is no endpoint to create them.

## 4. Concurrency and consistency

- Optimistic concurrency on drafts, settings, and templates via `If-Match: "<revision>"` / `ETag`; mismatch → 412.
- State-changing endpoints take `SELECT … FOR UPDATE` on the target row; invalid transitions → 409 `invalid_state`.
- Calculation runs: one active run per `(tenant, scope)`; second → 409 `run_in_progress`.

## 5. Security headers and CORS

Same-origin deployment (SPA and API under one host via Caddy), so CORS is **disabled by default**. If a separate origin is ever needed, use an explicit allow-list with credentials; never `*`. Responses carry `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`; HSTS and CSP set at Caddy (`SECURITY.md`).
